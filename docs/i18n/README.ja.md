## 更新時の困りごとをひとつの画面に

| 困りごと | このツールの対応 |
| --- | --- |
| デスクトップ版と CLI のどちらを更新するのか分からない | 現在のユーザーの公式 MSIX デスクトップ版と標準 npm CLI を検出します。複数のインストールは分けて表示し、選択したものだけを更新します。 |
| 接続が切れるたびにダウンロードをやり直す | 中断位置を保存します。CLI の大きなネイティブコンポーネントは再開可能な 1 MiB 単位で取得し、公式キャッシュは再検証後に再利用します。 |
| パッケージは準備できたが、まだ作業中 | 準備とインストールを分離します。インストール前に確認と実行中プロセスの検査を行い、Codex を強制終了しません。 |
| 成功と表示されたのに CLI が動かない | インストール後にバージョンを再検出し、CLI のバージョンコマンドも実行して一致を確認してから成功を報告します。 |
| テザリングの通信量が心配 | 従量制または料金不明のネットワークでは、大きなダウンロードを既定でブロックします。今回の取得を明示的に許可でき、npm インストール前にも料金状態を再確認します。 |
| C ドライブの空き容量が少ない | 必要容量と安全余裕を確認し、余裕がある場合だけ C を優先します。不足する場合は条件を満たす内蔵固定ドライブを検討し、キャッシュ場所を表示します。 |

**インストール前に公式パッケージの署名と内容のハッシュを検証します。** API key は不要です。アカウントトークンやチャットデータベースを読み取らず、テレメトリを収集せず、既存のランチャー設定も置き換えません。

## 4 ステップで開始

1. [Releases](https://github.com/son-gladyso/codex-update-center/releases) から `CodexUpdateCenter-*-win-x64.zip` を取得し、`SHA256SUMS.txt` で照合します。
2. 書き込み可能なフォルダーに展開し、`CodexUpdateCenter.exe` を実行します。.NET ランタイムは同梱されています。
3. 更新対象を選び、更新の確認と準備を開始します。対応するインストールがひとつだけの場合、既定では自動で選択して準備します。この起動時の自動準備は無効にできます。
4. 候補の検証後、作業を保存して対象の Codex を通常の方法で終了し、インストールを確認します。完了後に再検出されたバージョンを確認してください。

カスタム npm ディレクトリが見つからない場合は手動で追加できます。Codex がまだない場合は、ウィンドウに公式のインストール手順を表示します。

> **コミュニティプレビュー版**で、商用 Authenticode 署名はありません。実行のために Windows のセキュリティを無効にしないでください。クリーンな Windows 環境での展開互換性マトリクス、実機でのアクセシビリティ試験、一部のプロキシ・ネットワーク条件は未検証です。[検証記録](../VALIDATION.md)を参照してください。

## 対応するインストール

| 方式 | 対応範囲 |
| --- | --- |
| 現在のユーザーの、公式 Store 署名付き `OpenAI.Codex` x64 デスクトップ版 | 公式 MSIX の検出・署名検証後、Windows 展開サービス経由で更新します。実際の Windows 展開は、完全な受け入れ検証がまだ必要です。 |
| 標準 Node.js/npm による安定版 `@openai/codex` グローバルインストール | メインパッケージと Windows ネイティブコンポーネントを検証し、確認後に更新します。隔離ディレクトリでの実更新を検証済みです。 |
| 複数の npm グローバルディレクトリ、デスクトップ版と CLI の併用 | 別々に表示し、1 回に 1 件を更新します。npm プレフィックスの手動追加に対応します。 |
| ポータブルコピー、独自の複数インスタンス用ランチャー、WSL、ARM64、リンクを用いる Node バージョン管理環境 | 自動管理の対象外です。元のインストールツールを使用してください。 |

デスクトップ版と CLI は別々に管理されます。独立した CLI をデスクトップアプリ内に入れることはありません。キャッシュを別ドライブに置いても、Windows が管理するデスクトップ版のインストール場所は変わりません。

## 問題発生時の結果も明確に

- 一時停止やウィンドウを閉じた後も中断位置を保持します。ユーザーが明示的に停止したダウンロードは自動再開しません。
- 失敗、中断、バージョン未確認の場合は再確認を促します。**インストーラーが戻っただけでは成功と判定しません。**
- npm インストールはアトミックではなく、失敗後に npm の修復が必要な場合があります。自動ロールバックは保証しません。
- Codex の強制終了、古い候補へのダウングレード、アカウントやチャットの移行、常駐バックグラウンドサービスの起動は行いません。
- システムの有効なプロキシを使い、TLS 検証を維持します。VPN ノードを操作せず、最大速度やすべてのネットワークでの高速取得も保証しません。一部のプロキシでは npm インデックス要求が失敗する可能性があり、キャッシュと失敗記録は保持します。

[サポートとトラブル対応](../SUPPORT.md)も参照してください。状態は `%LOCALAPPDATA%\CodexUpdateCenter\Public` に保存され、キャッシュ場所はタスク画面に表示されます。このツールを削除しても Codex は削除されません。クリーンアップ前に状態とキャッシュファイルを確認してください。

## 検証済みの範囲

- **81 件のプログラムテスト**：対象の変更、不正な署名、ダウンロード再開、並行処理ロック、一時停止、インストール時の通信料金ゲートを対象とします。
- **10 件のリリースツール検査**：パッケージ改ざん、隠しファイルの欠落、範囲外パス、ソースのプライバシー境界を確認します。
- 新しい隔離ディレクトリで **CLI 0.161.0 → 0.162.1** の実更新を行い、新しい CLI を実行してバージョンを確認しました。既存のインストールマニフェストは変化していません。
- 公式デスクトップパッケージは Windows の署名検証と全ブロックのハッシュ検証に合格しました。ソースパッケージからの独立ビルドと実行パッケージの展開・起動も検証済みです。

実更新試験では再検証した公式パッケージと npm メタデータのキャッシュを再利用しました。**コールドキャッシュでのネットワーク試験成功を意味しません。** 署名・ハッシュ検証は実際の Windows 展開成功を意味しません。最新の自動実行は [GitHub Actions](https://github.com/son-gladyso/codex-update-center/actions)、詳しい範囲と未検証項目は [VALIDATION](../VALIDATION.md) にあります。

## まずはインストールせずに確認

環境に合うか判断するには、展開して検出されたインストールと現在のバージョンを確認してください。すぐにインストールを承認する必要はありません。準備では通信とダウンロードが発生します。対応するインストールがひとつだけの場合の自動準備は無効にできます。

- 実行：Windows x64 と書き込み可能な展開先。.NET 同梱、API key 不要。
- 確認・準備：公式ソースへのアクセスが必要です。プロキシ、通信料金ゲート、ディスク余裕の条件が適用されます。
- インストール：作業を保存し、選んだ Codex を通常終了し、対象を再確認してから、準備ができた時だけ承認します。

**最初の成功基準：** 選択したインストールの種類、場所、バージョンを特定でき、検証状態やブロック理由を理解できることです。更新の成功は、インストール後の必要な確認が済んでから判断します。

## よくある質問

**デスクトップ版と CLI は同じインストールですか？** いいえ。個別に検出・更新します。CLI のバージョン結果はデスクトップ展開の証拠ではありません。

**ポータブル版や独自の複数インスタンス構成が出ないのはなぜですか？** 自動管理の対象外です。元のインストールツールを使い、対応する構成に見せかけないでください。

**ダウンロード済みでもインストールできないのは？** 候補の検証、対象の確認、実行中プロセスや通信料金などのゲートが残っているためです。取得完了とインストール完了は別です。

**料金不明でもダウンロードを止めるのは？** 既定の料金保護です。ネットワークを確認し、適切なら今回の取得を明示的に許可してください。TLS や署名検証を弱める必要はありません。

**失敗したら旧版に戻りますか？** 保証はありません。npm インストールはアトミックではありません。繰り返し承認せず、結果と[サポートガイド](../SUPPORT.md)を確認してください。

**Windows が警告する場合は？** プレビューには商用 Authenticode 署名がありません。配布元とチェックサムを確認し、セキュリティを無効にしないでください。信頼できると確認できなければ実行しないでください。

### 変更する前に責任範囲を確認

| 領域 | ソース入口 | PR に記載すること |
| --- | --- | --- |
| 検出と対象選択 | `src/UpdateCenter.Core/Discovery.cs` | 誤った対象への更新をどう防ぎ、非対応構成をどう扱うか。 |
| 公式ネットワークと検証 | `OfficialNetwork.cs`, `Verification.cs` | 信頼検査を弱めず、失敗・再開・拒否時の観測結果を説明すること。 |
| 更新フローと永続化 | `UpdateService.cs`, `Storage.cs` | 一時停止、中断、再起動後の状態、インストール後検証。 |
| UI とメッセージ | `src/UpdateCenter.App/MainWindow.xaml` とコードビハインド | 操作の繰り返し、状態遷移、エラーメッセージの回帰検証。 |
| ビルドとリリース | `scripts/`, `docs/RELEASING.md` | 実際の監査、テスト、マニフェスト検査結果。 |

短い Core ファイル名は `src/UpdateCenter.Core/` 配下です。[アーキテクチャ](../ARCHITECTURE.md)を参照してください。成功を返すシミュレーションだけでは、ネイティブ Windows 展開の証明にはなりません。

## 開発と貢献

Windows x64、PowerShell 7、`global.json` 指定の SDK でビルドします。

```powershell
pwsh -File scripts/build.ps1 -Output artifacts/release-local
```

リリースゲートではソース監査、ロック済み依存関係の復元、テスト、ランタイム同梱パッケージの生成、ファイルごとのリリースマニフェスト検査を行います。出力先は新しいディレクトリにしてください。通常のテストは Codex をインストール・変更しません。Windows CI と隔離されたネイティブ受け入れ試験では、証拠の範囲を分けています。

有用な報告には、インストール方式、Windows バージョン、つまずいた手順、期待する結果を含めてください。[問題・提案テンプレート](https://github.com/son-gladyso/codex-update-center/issues/new/choose)を使い、認証情報、チャット、アカウントの生ログを添付しないでください。小さく再現可能な修正や、分かりやすい失敗メッセージを歓迎します。

### 最初の貢献

- **文書とメッセージ：** 実際に遭遇した失敗を再現手順にしたり、インストール種別、キャッシュ場所、エラー表示を分かりやすくしたりします。
- **回帰テスト：** 対象変更、一時停止・再開、パッケージ検証失敗などの境界をカバーし、観測できる結果を説明します。
- **Windows 検証：** 正確な OS、インストール方式、バージョン、試験範囲を記録し、合成テスト、ネイティブ操作、オンライン検証を区別します。
