## Для сложных моментов обновления

- **Непонятно, какую установку обновлять?** Находит официальные MSIX текущего пользователя и стандартные префиксы npm CLI. Несколько установок показываются отдельно; обновляется одна выбранная цель.
- **Загрузка прервалась?** Сохраняет точки продолжения и повторно использует заново проверенные официальные пакеты. Крупные нативные пакеты CLI загружаются возобновляемыми диапазонами по 1 MiB.
- **Работа ещё идёт?** Подготовка и установка разделены. Перед установкой нужны подтверждение и проверка работающих процессов; инструмент никогда не завершает Codex принудительно.
- **Объявлен успех, но CLI не запускается?** Перед сообщением об успехе повторно обнаруживает установленную версию и действительно выполняет команду версии CLI.
- **Мобильная точка доступа или мало места?** Крупные загрузки в тарифицируемой сети или сети с неизвестной стоимостью блокируются без явного разрешения. Проверяется бюджет диска; C предпочтителен только при достаточном резерве.

API key не нужен. Инструмент не читает токены аккаунтов или базы чатов, не собирает телеметрию и не заменяет конфигурацию вашего средства запуска. Перед установкой проверяются подписи официальных пакетов и хеши содержимого.

## Начните за четыре шага

1. Скачайте `CodexUpdateCenter-*-win-x64.zip` из [Releases](https://github.com/son-gladyso/codex-update-center/releases) и проверьте `SHA256SUMS.txt`.
2. Распакуйте в доступную для записи папку и запустите `CodexUpdateCenter.exe`. Среда .NET включена.
3. Выберите установку и подготовьте обновление. Единственная поддерживаемая установка по умолчанию выбирается и подготавливается автоматически; эту настройку можно отключить.
4. Сохраните работу, нормально выйдите из выбранного Codex и подтвердите установку. Проверьте подтверждённую итоговую версию.

Можно добавить собственные префиксы npm. Переносимые копии, нестандартные средства запуска нескольких экземпляров, WSL, ARM64 и схемы Node version manager с ссылками автоматически не обновляются.

## Поддерживаемые установки и детали работы

| Установка | Поддержка |
| --- | --- |
| Официальная настольная `OpenAI.Codex` x64 текущего пользователя с подписью Store | Обнаружение и проверка официального MSIX, обновление через службы развёртывания Windows. Полная приёмка реального развёртывания Windows ещё не выполнена. |
| Стабильная глобальная `@openai/codex` в стандартном Node.js/npm | Обнаружение, проверка основного пакета и нативных компонентов Windows, обновление после подтверждения; реальное обновление проверено в изолированном каталоге. |
| Несколько глобальных npm-каталогов или настольное приложение рядом с CLI | Показываются отдельно, обновляются по одному; префиксы npm можно добавить вручную. |
| Переносимые копии, нестандартные многоэкземплярные средства запуска, WSL, ARM64, связанные ссылками схемы Node version manager | Автоматического управления нет; используйте исходный инструмент установки. |

Настольное приложение и CLI обслуживаются отдельно: инструмент не вставляет отдельный CLI в настольное приложение. Перенос кэша на другой диск не меняет расположение настольной установки, управляемое Windows. Если Codex ещё не установлен, окно предлагает официальные инструкции.

Перед npm-установкой стоимость сети проверяется повторно. Если на C недостаточно резерва, рассматриваются подходящие внутренние фиксированные диски и показывается расположение кэша. Точки продолжения сохраняются при паузе или закрытии окна; явная пользовательская пауза сама не снимается.

После сбоя, прерывания или неподтверждённой установки предлагается повторная проверка; простой возврат установщика не означает успех. Инструмент не понижает версию до более старого кандидата, не переносит аккаунты и чаты и не запускает постоянно работающую фоновую службу. Запросы индекса npm могут не работать с некоторыми прокси; кэш и записи сбоев сохраняются. Перед очисткой проверьте файлы состояния и кэша.

81 программный тест охватывает изменение целей, недействительные подписи, возобновление, конкурентные блокировки, паузу и проверки стоимости сети при установке. 10 проверок средств выпуска охватывают подмену пакетов, пропуск скрытых файлов, выход за допустимые пути и границы приватности исходников. Изолированное обновление CLI не изменило манифесты прежних установок. Также проверены независимая сборка исходного пакета и распаковка/запуск пакета со средой выполнения.

Проверки выпуска аудируют исходники, восстанавливают зафиксированные зависимости, запускают тесты, создают автономные пакеты и проверяют манифесты. Выходной каталог должен быть новым; обычные тесты не устанавливают и не изменяют Codex. В обратной связи указывайте версию Windows и используйте [шаблоны проблем или предложений](https://github.com/son-gladyso/codex-update-center/issues/new/choose). См. также [журнал изменений](../../CHANGELOG.md). Архивы выпуска не содержат Codex.

## Честные ограничения предварительной версии

Это **предварительная версия сообщества** без коммерческой подписи Authenticode. Не отключайте защиту Windows для запуска. Матрица развёртывания на чистой Windows, проверка доступности на физических устройствах и часть сценариев прокси/сети ещё не проверены.

В новом изолированном каталоге CLI действительно обновлён с 0.161.0 до 0.162.1 и успешно запущен с использованием повторно проверенных официальных пакетов и кэшированных метаданных npm. Это не результат сетевого теста с пустым кэшем. Официальный настольный MSIX прошёл проверку подписи и всех хешей блоков; реальное развёртывание Windows ещё не принято.

npm-установка не атомарна: после ошибки может потребоваться исправление средствами npm. Инструмент сообщает о неподтверждённых результатах и не обещает автоматический откат. Используется действующий системный прокси с проверкой TLS; инструмент не управляет узлами VPN и не обещает максимальную скорость.

Состояние: `%LOCALAPPDATA%\CodexUpdateCenter\Public`. Каталоги кэша показываются в представлении задач. Удаление этого инструмента не удаляет Codex.

## Начните с проверки, а не с установки

Чтобы понять, подходит ли инструмент вашей среде, распакуйте его и изучите обнаруженные установки и версии. Не нужно сразу подтверждать установку. Подготовка может использовать сеть и загружать файлы; единственная поддерживаемая установка по умолчанию выбирается и подготавливается автоматически, но эту настройку можно отключить.

- Для запуска: Windows x64 и папка распаковки с правом записи. .NET включён, API key не требуется.
- Для проверки/подготовки: доступ к официальным источникам с учётом прокси, стоимости сети и резерва диска.
- Для установки: сохраните работу, нормально закройте выбранный Codex, ещё раз проверьте цель и подтвердите только при готовности.

**Первый успешный результат:** вы можете определить тип, расположение и версию выбранной установки и понять состояние проверки или блокировки. Обновление успешно только после требуемых проверок результата установки.

## Частые вопросы

**Настольное приложение и CLI — одна установка?** Нет. Они обнаруживаются и обновляются отдельно; результат версии CLI не доказывает развёртывание настольного приложения.

**Почему нет моей переносимой копии или нестандартной многоэкземплярной схемы?** Эти схемы вне автоматического управления. Пользуйтесь исходным инструментом, не маскируйте их под поддерживаемую установку.

**Почему после загрузки установка заблокирована?** Ещё нужны проверка кандидата, подтверждение цели и применимые проверки работающих процессов/стоимости сети. Конец загрузки не равен концу установки.

**Зачем блокировать загрузку при неизвестной стоимости сети?** Это стандартная защита расходов. Проверьте сеть и при необходимости явно разрешите текущую загрузку; не ослабляйте TLS или проверку подписей.

**Вернётся ли старая версия автоматически после сбоя?** Гарантии отката нет. npm-установка не атомарна. Изучите результат и [руководство поддержки](../SUPPORT.md), а не многократно подтверждайте установку.

**Что делать с предупреждением Windows об инструменте?** У предварительной версии нет коммерческой Authenticode-подписи. Проверьте источник и контрольные суммы, не отключайте защиту системы; при невозможности установить доверие не запускайте программу.

### С чего начать первое участие

- **Документация и сообщения:** превратите наблюдавшийся сбой в воспроизводимые шаги или понятнее опишите типы установок, кэш и ошибки.
- **Регрессионные тесты:** охватите изменение цели, паузу/возобновление или ошибку проверки пакета и объясните наблюдаемый результат.
- **Проверка Windows:** запишите точную систему, способ установки, версии и область тестирования. Отделяйте синтетические тесты, нативные операции и сетевую проверку.

Прочтите [руководство участника](../../CONTRIBUTING.md) и [запись проверок](../VALIDATION.md), затем выберите узкую задачу. Реальную установку проверяйте в изолированной среде; не используйте повседневную рабочую установку как тестовую по умолчанию. Прежде чем объявить новый тип установки поддерживаемым, обсудите обнаружение, механизм обновления и обработку ошибок.

Сейчас страница показывает снимок настоящего приложения с примерными данными, а не непрерывную запись от подготовки до завершённой установки. Улучшения воспроизводимых инструкций приветствуются, но демонстрационные состояния нельзя выдавать за реальные результаты обновления.
