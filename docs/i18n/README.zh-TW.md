<a id="这些麻烦交给一个窗口"></a>

## 這些麻煩，交給一個視窗

| 你遇到的問題 | 工具如何處理 |
| --- | --- |
| “裝的是桌面版還是 CLI？應該更新哪一個？” | 識別當前使用者的官方桌面安裝和標準 npm CLI；多個安裝分別列出，只更新你選中的一個。 |
| “網路斷了，又要從頭下載？” | 保留下載斷點；CLI 大型原生元件按 1 MiB 分段下載，已取得的官方快取驗證後可重複使用。 |
| “包下好了，但我還在工作。” | 準備與安裝分開；安裝前需要你確認，並檢查所選 Codex 是否仍在執行，不強行結束工作程序。 |
| “命令說成功了，實際還是打不開。” | 安裝後重新識別目標版本；CLI 還要實際執行版本查詢，匹配才報告成功。 |
| “手機熱點不想被背景下載吃光。” | 計費或費用未知網路預設阻止大包下載，npm 安裝前再次檢查；可以明確放行本次下載。 |
| “C 盤快滿了，快取會放哪裡？” | 先檢查預算和安全餘量；C 盤足夠時優先使用，不足時考慮符合條件的內部固定盤，並顯示快取位置。 |

**安裝包來自官方來源，安裝前驗證簽名和內容。** 工具不需要 API key，不讀取帳號權杖或聊天資料庫，也不上傳遙測，不替換你的啟動器設定。

<a id="开始使用"></a>

## 開始使用

1. 在 [Releases](https://github.com/son-gladyso/codex-update-center/releases) 下載 `CodexUpdateCenter-*-win-x64.zip`，按同頁 `SHA256SUMS.txt` 核對檔案。
2. 解壓到可寫目錄，開啟 `CodexUpdateCenter.exe`，不需要另外安裝 .NET。
3. 選擇要更新的安裝，點選 **檢查並準備更新**。只有一個支援安裝時，預設自動選中並準備；可取消“開啟後自動檢查並準備”。
4. 等候選驗證完成，儲存工作並正常退出所選 Codex，再點選 **確認安裝**。完成後檢視重新檢測的版本。

找不到自訂 npm 目錄時，使用 **新增 npm 安裝目錄**。首次還沒裝 Codex 時，視窗提供官方安裝說明。

> 當前是 **社群預覽版**，適合願意回饋問題的 Windows 使用者。工具本體尚無商業 Authenticode 簽名；不要關閉系統安全功能來執行。Windows 部署相容性矩陣、實體裝置無障礙測試及部分代理/網路場景尚未驗證，具體範圍見[驗證記錄](../VALIDATION.md)。

<a id="哪些安装可以更新"></a>

## 哪些安裝可以更新？

| 安裝方式 | 支援情況 |
| --- | --- |
| 當前使用者的官方 Store 簽名 `OpenAI.Codex` x64 桌面安裝 | 識別、驗籤官方 MSIX，透過 Windows 部署服務更新。實際 Windows 部署仍待完整驗收。 |
| 標準 Node.js/npm 的穩定版 `@openai/codex` 全域安裝 | 識別、驗證主包及 Windows 原生元件、確認後更新；已做隔離目錄真實升級驗證。 |
| 多個 npm 全域目錄、桌面版與 CLI 並存 | 分別顯示，一次更新一項；可手動新增 npm 字首。 |
| 可攜複製版、自訂多執行個體啟動器、WSL、ARM64、連結式 Node 版本管理器 | 不自動接管；使用原安裝工具。 |

桌面版和 CLI 分別維護，工具不會把獨立 CLI 塞進桌面應用。下載快取放在其他盤，也不會改變 Windows 管理的桌面應用安裝位置。

<a id="出问题时结果说清楚"></a>

## 出問題時，結果說清楚

- 下載暫停或視窗關閉後保留斷點；使用者主動暫停後不自行恢復下載。
- 安裝失敗、中斷或無法確認版本時提示重新檢查，**不會把“安裝器返回了”當作成功**。
- npm 安裝不是不可分割的交易，失敗後可能需要 npm 修復；當前不承諾自動回滾。
- 不強制結束 Codex、不降級到較舊候選、不遷移帳號和聊天，不啟動背景常駐服務。
- 網路採用系統有效代理，保留 TLS 驗證；不控制 VPN 節點或承諾所有網路都能高速下載。npm 索引請求在部分代理下仍可能失敗，快取和失敗記錄會保留。

更多情況見[支援與故障處理](../SUPPORT.md)。狀態位於 `%LOCALAPPDATA%\CodexUpdateCenter\Public`，快取位置可在任務介面檢視。解除安裝本工具不解除安裝 Codex；清理前先核對狀態和快取檔案。

<a id="我们如何确认它能用"></a>

## 我們如何確認它能用

- **81 項程式測試**，覆蓋更新目標變化、無效簽名、下載續傳、併發鎖、暫停與安裝費用門禁。
- **10 項發布工具檢查**，覆蓋包篡改、隱藏檔案遺漏、越界路徑和原始碼隱私邊界。
- 在新隔離目錄實際完成 **CLI 0.161.0 → 0.162.1**，執行新 CLI 驗證版本，原有安裝清單保持一致。
- 官方桌面包已透過 Windows 驗籤及全部塊雜湊檢查；原始碼包獨立建置、執行包解壓啟動均已驗證。

真實升級測試重複使用了官方包與 npm 索引快取，**不等同冷快取聯網透過**；包驗籤不等同真實 Windows 部署透過。最新自動化執行見 [GitHub Actions](https://github.com/son-gladyso/codex-update-center/actions)，詳細範圍及待驗收項見 [VALIDATION](../VALIDATION.md)。

<a id="先完成一次不安装的检查"></a>

## 先完成一次不安裝的檢查

如果只是想判斷它是否適合你的環境，先解壓執行、檢視發現的安裝和當前版本，不必馬上確認安裝。準備更新可能觸發聯網與下載；單個支援安裝預設會自動選中並準備，可關閉“開啟後自動檢查並準備”。

- 普通執行：Windows x64 與可寫解壓目錄，自帶 .NET，無需 API key。
- 檢查/準備：需要存取官方來源，受代理、網路費用門禁和磁碟餘量影響。
- 真正安裝：儲存工作、正常退出選中的 Codex，並再次核對目標；只在準備好後點確認安裝。

**第一次成功的標準：**你能辨認選中的安裝方式、位置和版本，理解候選驗證或阻斷提示。只有安裝後的重新檢測符合要求，才能把升級記為成功。

<a id="常见问题"></a>

## 常見問題

**桌面版和 CLI 是同一個安裝嗎？** 不是。兩者分別識別、分別更新；不要把 CLI 版本結果當作桌面版部署證據。

**為什麼沒識別我的可攜版或自訂多執行個體？** 這些不在自動接管範圍。使用原安裝工具，不要為了讓它出現而偽裝成受支援安裝。

**下載完成為什麼還不能安裝？** 還需要驗證候選、確認目標，並滿足執行程序與網路費用等門禁。下載完成不是安裝完成。

**為什麼網路費用未知也會阻止下載？** 這是預設的費用保護。核對網路情況後可明確放行本次下載，不需要關閉 TLS 或簽名檢查。

**失敗後會自動恢復舊版本嗎？** 不承諾。npm 安裝並非不可分割的交易；先檢視具體結果與[故障處理](../SUPPORT.md)，不要盲目反覆點選安裝。

**系統對工具本體給出安全提醒怎麼辦？** 當前預覽版沒有商業 Authenticode 簽名。核對來源與校驗資訊，不要關閉系統安全功能；無法確認時不要執行。

<a id="修改之前先找到责任边界"></a>

### 修改之前，先找到責任邊界

| 要改進的部分 | 原始碼入口 | PR 中需要說明 |
| --- | --- | --- |
| 安裝發現與目標選擇 | `src/UpdateCenter.Core/Discovery.cs` | 如何避免選錯執行個體，以及不支援的佈局如何處理。 |
| 官方網路與包驗證 | `OfficialNetwork.cs`、`Verification.cs` | 失敗、斷點或拒絕場景的實際觀察；不能放寬可信來源與校驗。 |
| 更新流程與狀態 | `UpdateService.cs`、`Storage.cs` | 暫停、中斷、重啟後狀態及安裝結果如何重新核對。 |
| 介面與提示 | `src/UpdateCenter.App/MainWindow.xaml` 及程式碼後置檔案 | 重複操作、狀態變化和錯誤提示的迴歸驗證。 |
| 建置與發布 | `scripts/`、`docs/RELEASING.md` | 原始碼審計、測試與清單檢查的實際結果。 |

Core 表中的短檔名均位於 `src/UpdateCenter.Core/`。完整關係見[架構說明](../ARCHITECTURE.md)，不要僅憑一個模擬成功返回值聲稱 Windows 部署透過。


<a id="开发与参与"></a>

## 開發與參與

需要 Windows x64、PowerShell 7 和 `global.json` 指定的 SDK：

```powershell
pwsh -File scripts/build.ps1 -Output artifacts/release-local
```

發布門禁會審計原始碼、鎖定恢復依賴、執行測試、生成自帶執行時的包並校驗清單。輸出目錄必須是新目錄；普通測試不會安裝或修改 Codex。

[架構說明](../ARCHITECTURE.md) · [貢獻指南](../../CONTRIBUTING.md) · [發布流程](../RELEASING.md) · [更新記錄](../../CHANGELOG.md) · [安全政策](../../SECURITY.md)

**最有幫助的回饋**：你的安裝方式、Windows 版本、卡在哪一步，以及期望看到什麼結果。請用[問題或建議模板](https://github.com/son-gladyso/codex-update-center/issues/new/choose)，不要貼權杖、聊天內容或原始帳號記錄。歡迎提交能復現問題的測試，以及讓失敗提示更清楚的小改進。

<a id="第一次贡献可以从哪里开始"></a>

### 第一次貢獻，可以從哪裡開始？

- **文件與提示**：把一個真實遇到的失敗整理成可重現步驟，或讓安裝型別、快取位置和錯誤提示更容易理解。
- **迴歸測試**：補充目標安裝變化、暫停恢復、包校驗失敗等邊界場景，並說明觀察到了什麼結果。
- **Windows 驗證**：記錄準確的系統、安裝方式、版本與測試範圍，明確區分合成測試、原生操作和聯網驗證。

先閱讀[貢獻指南](../../CONTRIBUTING.md)和[驗證記錄](../VALIDATION.md)，再選一個範圍明確的問題。涉及真實安裝的驗證請使用隔離環境，不要把日常工作安裝當作預設測試目標。提出新安裝方式時，先討論發現規則、更新機制與失敗處理，不直接把它寫成已支援。

本頁目前展示的是實際程式的示例資料截圖，尚未提供從準備到安裝完成的連續錄影。歡迎改進可重現說明，但不要用示範狀態冒充真實升級結果。

MIT 授權條款適用於本工具程式碼。發行包不包含 Codex 軟體；執行時從官方來源下載，相關軟體的授權條款與條款獨立適用。依賴宣告見 [NOTICE](../../NOTICE.md)。
