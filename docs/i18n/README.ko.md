### Windows에서 Codex를 조금 더 간편하게 업데이트하세요.

**설치 위치 검색, 검증된 공식 업데이트 준비, 실제 설치 결과 확인을 한 창에서 진행합니다.** 설치 폴더를 반복해서 찾거나 큰 패키지를 다시 받거나, “업데이트했는데 실행되지 않는” 문제를 조사하는 부담을 줄입니다.

[![Windows build](https://github.com/son-gladyso/codex-update-center/actions/workflows/build.yml/badge.svg?branch=main)](https://github.com/son-gladyso/codex-update-center/actions/workflows/build.yml)

[Windows 미리 보기 다운로드](https://github.com/son-gladyso/codex-update-center/releases) · [문제 신고](https://github.com/son-gladyso/codex-update-center/issues/new/choose)

Windows x64 · 압축 해제 후 실행, .NET 포함 · MIT · OpenAI와 무관한 독립 커뮤니티 프로젝트

![설치 목록, 후보 검증, 네트워크 비용 및 설치 확인](../images/update-center.png)

*실제 앱에 인공적인 예제 데이터를 표시한 화면입니다. 현재 UI는 중국어입니다. 실제 사용자 설치가 업데이트되었다는 증거는 아닙니다.*

## 업데이트할 때의 번거로움을 한 창에서

| 겪는 문제 | 도구의 처리 방식 |
| --- | --- |
| 데스크톱 앱과 CLI 중 무엇을 업데이트해야 할지 모르겠음 | 현재 사용자의 공식 MSIX 데스크톱 설치와 표준 npm CLI를 검색합니다. 여러 설치는 별도로 표시하며 선택한 대상만 업데이트합니다. |
| 연결이 끊기면 다운로드를 처음부터 다시 해야 함 | 중단 지점을 저장합니다. 큰 CLI 네이티브 구성 요소는 재개 가능한 1 MiB 단위로 다운로드하며 공식 캐시는 다시 검증한 뒤 재사용합니다. |
| 패키지는 준비됐지만 아직 작업 중임 | 준비와 설치를 분리합니다. 설치 전 확인과 실행 중 프로세스 검사를 요구하며 Codex를 강제로 종료하지 않습니다. |
| 성공이라고 표시되지만 CLI가 실행되지 않음 | 설치 버전을 다시 검색하고 CLI 버전 명령도 실행하여 결과가 일치해야 성공으로 보고합니다. |
| 휴대폰 핫스폿의 데이터 사용량이 걱정됨 | 요금제 연결 또는 비용을 알 수 없는 네트워크에서는 큰 다운로드를 기본 차단합니다. 현재 다운로드를 명시적으로 허용할 수 있고 npm 설치 전에도 비용을 다시 확인합니다. |
| C 드라이브 공간이 부족함 | 필요 용량과 안전 여유를 확인하며 충분할 때만 C를 우선합니다. 부족하면 조건에 맞는 내부 고정 디스크를 검토하고 캐시 위치를 표시합니다. |

**설치 전에 공식 패키지의 서명과 콘텐츠 해시를 검증합니다.** API key가 필요하지 않습니다. 계정 토큰이나 채팅 데이터베이스를 읽지 않으며, 원격 측정 정보를 수집하거나 기존 실행기 설정을 교체하지 않습니다.

## 네 단계로 시작하기

1. [Releases](https://github.com/son-gladyso/codex-update-center/releases)에서 `CodexUpdateCenter-*-win-x64.zip`을 받고 `SHA256SUMS.txt`로 확인합니다.
2. 쓰기 가능한 폴더에 압축을 풀고 `CodexUpdateCenter.exe`를 실행합니다. .NET 런타임이 포함되어 있습니다.
3. 업데이트할 설치를 선택하고 업데이트 확인 및 준비를 시작합니다. 지원되는 설치가 하나뿐이면 기본적으로 자동 선택하고 준비합니다. 이 시작 시 자동 준비 옵션은 끌 수 있습니다.
4. 후보 검증이 끝나면 작업을 저장하고 해당 Codex를 정상 종료한 다음 설치를 확인합니다. 완료 후 다시 검색된 버전을 살펴보세요.

사용자 지정 npm 폴더가 검색되지 않으면 직접 추가할 수 있습니다. Codex가 아직 설치되지 않았다면 창에서 공식 설치 안내를 제공합니다.

> **커뮤니티 미리 보기**이며 상용 Authenticode 서명이 없습니다. 실행을 위해 Windows 보안 기능을 끄지 마세요. 새 Windows 환경의 배포 호환성 매트릭스, 실제 장치의 접근성 검사, 일부 프록시 및 네트워크 조건은 아직 검증되지 않았습니다. [검증 기록](../VALIDATION.md)을 참고하세요.

## 지원하는 설치 방식

| 설치 방식 | 지원 범위 |
| --- | --- |
| 현재 사용자의 공식 Store 서명 `OpenAI.Codex` x64 데스크톱 설치 | 공식 MSIX를 검색하고 서명을 검증한 뒤 Windows 배포 서비스로 업데이트합니다. 실제 Windows 배포는 아직 전체 인수 검증이 필요합니다. |
| 표준 Node.js/npm의 안정 버전 `@openai/codex` 전역 설치 | 기본 패키지와 Windows 네이티브 구성 요소를 검증하고 확인 후 업데이트합니다. 격리된 디렉터리에서 실제 업그레이드를 검증했습니다. |
| 여러 npm 전역 폴더 또는 데스크톱 앱과 CLI의 공존 | 따로 표시하고 한 번에 하나만 업데이트합니다. npm 접두 경로를 직접 추가할 수 있습니다. |
| 포터블 복사본, 사용자 지정 다중 인스턴스 실행기, WSL, ARM64, 링크 기반 Node 버전 관리자 구성 | 자동으로 관리하지 않습니다. 원래 설치 도구를 사용하세요. |

데스크톱 앱과 CLI는 별도로 유지됩니다. 독립 CLI를 데스크톱 앱에 넣지 않습니다. 다운로드 캐시를 다른 디스크로 옮겨도 Windows가 관리하는 데스크톱 설치 위치는 바뀌지 않습니다.

## 문제가 생겼을 때도 결과를 명확하게

- 일시 중지하거나 창을 닫아도 중단 지점을 유지합니다. 사용자가 직접 중지한 다운로드는 자동으로 재개하지 않습니다.
- 실패, 중단 또는 버전 확인 불가 상태에서는 다시 확인하도록 안내합니다. **설치 프로그램이 반환했다는 사실만으로 성공 처리하지 않습니다.**
- npm 설치는 원자적 작업이 아닙니다. 실패 후 npm 복구가 필요할 수 있으며 자동 롤백을 보장하지 않습니다.
- Codex 강제 종료, 더 오래된 후보로 다운그레이드, 계정이나 채팅 이동, 상주 백그라운드 서비스 시작은 하지 않습니다.
- 시스템의 유효 프록시 설정을 사용하고 TLS 검증을 유지합니다. VPN 노드를 제어하거나 최대 속도 및 모든 네트워크의 고속 다운로드를 보장하지 않습니다. 일부 프록시에서는 npm 인덱스 요청이 실패할 수 있으며 캐시와 실패 기록은 보존합니다.

[지원 및 문제 해결](../SUPPORT.md)을 참고하세요. 상태는 `%LOCALAPPDATA%\CodexUpdateCenter\Public`에 저장되며 캐시 위치는 작업 화면에 표시됩니다. 이 도구를 제거해도 Codex는 제거되지 않습니다. 정리하기 전에 상태와 캐시 파일을 확인하세요.

## 검증한 범위

- **프로그램 테스트 81개**: 대상 변경, 잘못된 서명, 다운로드 재개, 동시 실행 잠금, 일시 중지, 설치 시 네트워크 비용 게이트를 다룹니다.
- **릴리스 도구 검사 10개**: 패키지 변조, 숨김 파일 누락, 범위를 벗어난 경로, 소스의 개인정보 경계를 검사합니다.
- 새 격리 디렉터리에서 **CLI 0.161.0 → 0.162.1** 실제 업그레이드를 수행하고 새 CLI를 실행하여 버전을 검증했습니다. 기존 설치 매니페스트는 유지되었습니다.
- 공식 데스크톱 패키지는 Windows 서명 및 모든 블록 해시 검사를 통과했습니다. 소스 패키지의 독립 빌드와 실행 패키지의 압축 해제 및 실행도 검증했습니다.

실제 업그레이드 테스트는 다시 검증한 공식 패키지와 npm 메타데이터 캐시를 재사용했습니다. **캐시가 없는 네트워크 환경에서 성공했다는 의미는 아닙니다.** 서명 및 해시 검증은 실제 Windows 배포 성공을 의미하지 않습니다. 최신 자동 실행은 [GitHub Actions](https://github.com/son-gladyso/codex-update-center/actions), 상세 범위와 미검증 항목은 [VALIDATION](../VALIDATION.md)에 있습니다.

## 설치하기 전에 먼저 살펴보기

내 환경에 적합한지 판단하려면 압축을 풀고 검색된 설치와 현재 버전을 확인하세요. 바로 설치를 승인할 필요는 없습니다. 준비 과정에서는 네트워크와 다운로드를 사용할 수 있습니다. 지원되는 설치가 하나일 때의 자동 준비는 끌 수 있습니다.

- 실행: Windows x64와 쓰기 가능한 압축 해제 폴더. .NET 포함, API key 불필요.
- 확인 및 준비: 공식 소스 접근이 필요하며 프록시, 네트워크 비용 게이트, 디스크 여유 조건의 영향을 받습니다.
- 설치: 작업을 저장하고 선택한 Codex를 정상 종료한 뒤 대상을 다시 확인하세요. 준비되었을 때만 설치를 승인하세요.

**첫 성공의 기준:** 선택한 설치의 유형, 위치, 버전을 식별하고 후보 검증 상태나 차단 이유를 이해할 수 있어야 합니다. 업데이트 성공은 필요한 설치 후 검증이 끝난 뒤에만 판단합니다.

## 자주 묻는 질문

**데스크톱 앱과 CLI가 같은 설치인가요?** 아닙니다. 각각 검색하고 업데이트합니다. CLI 버전 결과는 데스크톱 배포의 증거가 아닙니다.

**포터블 버전이나 사용자 지정 다중 인스턴스 구성이 안 보이는 이유는요?** 자동 관리 범위 밖입니다. 원래 설치 도구를 사용하고 지원되는 설치처럼 위장하지 마세요.

**다운로드가 끝났는데 왜 설치할 수 없나요?** 후보 검증, 대상 확인, 실행 중 프로세스 및 네트워크 비용 등의 게이트를 통과해야 합니다. 다운로드 완료와 설치 완료는 다릅니다.

**비용을 알 수 없는 네트워크도 차단하나요?** 기본 비용 보호 장치입니다. 네트워크를 확인한 뒤 적절하면 현재 다운로드를 명시적으로 허용하세요. TLS나 서명 검증을 약화할 필요는 없습니다.

**실패하면 이전 버전으로 자동 복원되나요?** 롤백을 보장하지 않습니다. npm 설치는 원자적이지 않습니다. 설치를 반복 승인하지 말고 결과와 [지원 가이드](../SUPPORT.md)를 살펴보세요.

**Windows가 도구에 대해 경고하면 어떻게 하나요?** 미리 보기에는 상용 Authenticode 서명이 없습니다. 배포 출처와 체크섬을 확인하고 시스템 보안을 끄지 마세요. 신뢰 여부를 확인할 수 없으면 실행하지 마세요.

## 개발 및 기여

Windows x64, PowerShell 7, `global.json`에 지정된 SDK로 빌드합니다.

```powershell
pwsh -File scripts/build.ps1 -Output artifacts/release-local
```

릴리스 게이트는 소스 감사, 잠긴 종속성 복원, 테스트 실행, 런타임 포함 패키지 생성, 파일별 릴리스 매니페스트 검사를 수행합니다. 출력 폴더는 새 디렉터리여야 합니다. 일반 테스트는 Codex를 설치하거나 수정하지 않습니다. Windows CI와 격리된 네이티브 인수 검증은 증거 범위를 구분합니다.

유용한 피드백에는 설치 방식, Windows 버전, 막힌 단계와 기대한 결과를 포함하세요. [문제 또는 제안 템플릿](https://github.com/son-gladyso/codex-update-center/issues/new/choose)을 사용하고 자격 증명, 채팅 내용, 가공하지 않은 계정 로그를 첨부하지 마세요. 재현 가능한 작은 수정과 명확한 실패 메시지를 환영합니다.

### 첫 기여로 적합한 작업
