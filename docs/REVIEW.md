# 公开版代码审核

2026-10-15，逐模块检查、独立 AI 代码复核与自动测试相结合；这不等于第三方安全认证或真人 Windows 兼容性验收。0.1.0 的历史审核之后，0.1.1-preview 继续修复以下问题。

## 0.1.1-preview 复核修复

- 偏好和新增目录持久化失败时不提前提交内存，界面提示错误并恢复选择。
- 暂停先取消下载；写状态失败不能阻止取消。
- 安装超时或失败标为未确认，清空内存候选，不误报下载已暂停。
- 复用候选、准备原生组件及确认 npm 安装后重新检查网络费用；拒绝时不进入安装状态，保留候选供重试。
- 损坏或字段类型错误的 npm 清单不隐藏其他健康安装。
- 准备元数据六小时后重新查询；旧文件保留。
- 版本由统一属性派生；发布时检查标签、源码边界、清单完整性和隐藏文件。

独立复核最后指出的安装费用入口缺口已修复，并增加真实 STA WPF 行为回归；完整发行验证结果见 VALIDATION.md。测试使用隔离目录，不显示安装确认框、不执行真实安装。

## 0.1.0 已修正的问题

| 问题 | 修正与验证 |
| --- | --- |
| npm 可忽略原生组件失败并返回零退出码，版本文件会误导成功判断 | 原生 x64 组件作为显式安装目标；成功前用独立空白 CODEX_HOME 实际运行 --version，输出必须完全匹配 |
| npm 和程序使用不同网络代理，导致元数据可读但二进制下载失败 | 使用 .NET 解析到的系统有效代理，传入 npm 子进程；保持 TLS 和官方 registry 参数 |
| 大型原生包整包请求在代理下反复中断 | 1 MiB 范围下载，检查响应区间，保留完整/部分字节；整包 SHA-512 和 npm 发布签名通过后才进入 npm 缓存 |
| 下载过程中另一个工具可能更新所选安装 | 真正运行 npm 前重新检测版本、身份、进程和磁盘空间；发现变化停止，避免覆盖更新 |
| 短暂 TLS 连接中断直接终止元数据查询 | 仅对传输错误、超时及服务器错误做有限重试；权限错误、地址越界及校验失败保持拒绝 |
| 操作锁未检查链接路径 | 创建锁文件前执行本地路径和重解析点检查 |
| 发布流程缺失，无法确认交付内容 | 增加锁定恢复、强制测试、自带运行时发布、许可证收集、逐文件清单及 ZIP 摘要；源码使用明确目录白名单打包 |

## 保留的设计边界

- 更新器信任当前 Windows 用户和本机标准 Node/npm 工具，不对同权限恶意软件作隔离承诺。
- MSIX 更新由 Windows 部署服务完成；Windows 签名和文件块校验都必须通过。
- npm 不是原子安装器；中断后可能需要 npm 修复，不能宣称自动回滚。工具保存待复核状态并重新扫描。
- 发现多个安装时由用户选择；不遍历整个磁盘，不读取账户内容，不猜测任意自定义启动脚本。
- GitHub 工作流生成草稿预发行。仓库权限、私密漏洞报告、分支保护及商业代码签名由维护者在目标仓库配置。
- Windows 部署兼容性、辅助功能真人验收和物理设备场景见 [验证记录](VALIDATION.md)。
